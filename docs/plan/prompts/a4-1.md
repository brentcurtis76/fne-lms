## Acceptance criteria

- [A1] Both routes GET-only (405 otherwise). Serve from the `propuestas` bucket
  cache path `pasantias/<name>-<VERSION>.pdf` using `lib/propuestas/storage.ts`
  (`downloadFile`/`uploadFile`); on miss, generate via A3's `generateBrochure()`
  / `generateFicha()`, upload, then serve. **Upload failure degrades to
  generate-and-serve** (logged, still 200) — a broken bucket must not break the
  download.
- [A2] Headers: `Content-Type: application/pdf`; `Content-Disposition: inline`
  with an **RFC 5987-encoded** filename (es-CL names contain accents);
  `Cache-Control: public, max-age=3600`.
- [A3] A file pre-existing at the cache path is served **as-is** — this is D-05's
  manual-override path, and it is how the owner's designed brochure will be
  published. State that contract in the route's doc comment, and test it.
- [A4] Best-effort rate limit (`lib/rateLimit.ts`) — dampening only; the durable
  cost control is the cache.
- [A5] Tests: cache-hit path, generate-on-miss (uploads then serves),
  degrade-on-upload-failure, header assertions incl. the RFC 5987 encoding,
  405 on non-GET. Mock storage; use a small fixture so the suite stays fast.
- [A6] Gates green: `npm run type-check && npm run lint && npm test &&
  npm run build && node scripts/check-price-leak.mjs`. **The leak guard must
  stay green** — these are server routes, nothing commercial may reach a client
  chunk.
