## The finding

Generated cache fills use `upsert: true`. The cache path is also **D-05's
manual-override path — where the owner's Claude-designed brochure is published**.
So a transient read failure, or a generate racing a manual upload, lets a
*generated* PDF silently overwrite the *designed* one the owner published. The
override is the whole point of that path; a cache fill must never be able to
clobber it.

## Scope — `lib/pasantias/pdf/serve.ts` + tests

1. Generated fills become **create-only**. **Note the real shape of this:**
   `lib/propuestas/storage.ts`'s `uploadFile` hardcodes `upsert: true` and is
   **shared** with `pages/api/licitaciones/[id]/generate-propuesta.ts`, which
   legitimately overwrites when it regenerates a proposal — so do NOT flip the
   shared default. Either add an opt-in create-only option to `uploadFile`
   (default unchanged, so no existing caller changes behaviour) or have A4 call
   the storage client directly. Say which you chose and why.
   Also mind `uploadFile`'s 2-attempt retry loop: under create-only, a retry
   after a first attempt that actually succeeded will report already-exists —
   that must read as success, not failure.
   If the object already exists, that is success, not an error: someone else
   (a manual upload, or a concurrent request) already populated the path. Treat
   already-exists as a benign no-op, log at info, and serve the generated bytes
   for this request.
2. Distinguish it from a real upload failure (permissions, network): those keep
   the existing degrade-and-log-error behaviour. Match on the storage error
   shape rather than a message substring if the SDK exposes one; if it does not,
   say so in your report and match as narrowly as you can.
3. Tests: (a) create-only is what the code requests — assert the upload options,
   not just the call; (b) already-exists → 200, generated bytes served, no error
   log, info log instead; (c) genuine upload failure → still 200 with the error
   log (r2 behaviour intact); (d) the manual-override file, once present, is
   read and served as-is on the next request — i.e. prove the sequence
   "designed PDF uploaded → generated fill attempted → designed PDF still
   served" end to end with mocked storage.
4. The doc comment's D-05 paragraph should state the create-only rule as the
   mechanism that protects the override, not just as an implementation detail.
