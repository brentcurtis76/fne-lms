## B1 — the leak scanner does not catch ordinary Spanish prices

`scripts/check-price-leak.mjs` line 112 defines `CURRENCY = '(?:€|EUR)'`. Sol
injected `<p>Programa: 2500 euros por persona</p>`, the build succeeded, the
scanner reported clean and the D-02 Playwright test passed. Two gaps compound:
the currency alternation has no word forms, and `2500` without the thousands
separator misses `PRICE_AMOUNT_PATTERNS`, which pin the Spanish-formatted
`2.500`.

D-02 is a frozen decision. A guard that only catches the glyph is not a guard.

- Recognize the word forms case-insensitively — `euro`, `euros`, and `eur` as a
  standalone token — alongside `€`.
- Make the amount patterns match a figure with **or without** the thousands
  separator (`2500` and `2.500`; likewise the retired `1000`/`1.000`,
  `1560`/`1.560`, `560`). Keep the existing whole-amount boundaries: do not
  start matching `2500` inside `12500`.
- Keep the tuned `GAP`/`BAND_GAP` windows. If widening the currency alternation
  makes a window fire on a clean build, narrow the window — do not narrow the
  alternation. Re-verify the scanner is clean on an unmodified build; this repo
  ships unrelated euro-denominated code.
- **Add fail-on-mutant coverage** as an automated test, not a manual note: for
  each of `2500 euros`, `2.500 euros`, `2500 EUROS`, `€2.500`, a lodging-band
  pair (`70`/`120` beside a currency marker) and one commercial phrase, a
  fixture containing it must make the scanner exit non-zero, and a clean fixture
  must exit zero. Drive the scanner's matcher directly against fixture strings —
  do not run six production builds.
- Extend the page-level D-02 e2e prohibition to the same word forms.

## B2 — the fidelity guards are partial and self-referential

Sol changed La Maquinista's level to `ESO`, its first highlight to
`Innovación educativa`, and Jordi Musons's title to `Coordinador`. **All 83
targeted tests passed, the build passed, and all 4 e2e passed.**

Two distinct causes, and you must fix both:

1. **Partial pinning.** `__tests__/lib/pasantias-cohort.test.ts:275` pins four of
   seven school levels, two complete highlight lists, and a subset of expert
   titles. Everything unpinned is free to be wrong.
2. **Self-reference.** `tests/e2e/pasantias-page.spec.ts:61` reads its
   expectations from the same module it is checking, so the source and the
   expectation drift together. A test shaped like this can only ever prove the
   page renders what the module says — never that the module says the right
   thing. **This is the same failure class as the r2 bug**, one level up.

The fix is an **independent oracle**: a test-owned literal transcription of the
authoritative data, compared against the module.

- In the unit test, declare a `const` matrix transcribed by hand from Appendix
  A-5/A-6 and pack §5b: for all **seven** schools, name + tier + levels + the
  **full ordered highlight list**; for all **eight** experts, name + role +
  school + host note. Assert the module deep-equals it, both directions, so an
  added, removed, renamed or reordered entry fails.
- Keep this matrix as literals inside the test file. Do not import it from
  `cohort-public.ts`, do not derive it, do not read it from a shared fixture the
  module also uses.
- The e2e may keep reading the module for *rendering* assertions (that is its
  job), but add at least one literal-pinned assertion per section so a wholesale
  module corruption still fails at the page level.
- **Prove it**: apply Sol's three mutations one at a time and show the named
  failures for each. Then revert and show green.

(`pages/pasantias.tsx:649`) and the thirteen objective numbers

## B5 — the page defeats the production-origin security contract

`pages/pasantias.tsx:103` wraps `getAppBaseUrl` in a try/catch and, on failure,
rebuilds the origin from the request's `Host` header. `lib/utils/app-url.ts:8`
documents exactly why that must not happen: the `Host` header is
attacker-controlled, and in production the origin MUST come from configuration,
with a missing configuration a loud failure rather than a silent fallback.

The existing code comment argues the value is not durable because it only fills
meta tags. **That argument is wrong** — canonical and OG URLs are scraped,
cached and indexed by search engines and by WhatsApp, so a poisoned origin
outlives the request exactly the way the contract warns about. (This deviation
was accepted by the PM in r1. That acceptance was a mistake and is withdrawn.)

- Delete the try/catch. Call `getAppBaseUrl(context.req)` directly and let it
  throw.
- The real reason for the fallback was that CI's `npm run start` throws with no
  configured origin. Fix that where it belongs: the CI workflow already writes
  `.env.local` in the "Point the app at the local stack" step
  (`.github/workflows/ci.yml` ~line 134). Add
  `NEXT_PUBLIC_BASE_URL=http://localhost:3000` to that heredoc.
- Confirm the e2e passes with the catch gone and the env set.
