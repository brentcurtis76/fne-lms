## The defect

r5's claim of zero coverage lost is **false**. Confirmed independently by the PM
against `ca8e024`:

| shape | `ca8e024` | `2158c44` | |
|---|---|---|---|
| `€2 500\n7` | FIRES | miss | **regression** |
| `€2 500 7` | FIRES | miss | **regression** |
| `€1 000\n45` | FIRES | miss | **regression** |
| `€2 500 7` | FIRES | miss | **regression** |
| `€1 560 45` | FIRES | FIRES | ok |
| `€2 500` | FIRES | FIRES | ok |
| `€2500\n7` | FIRES | FIRES | ok |

Cause: `whitespaceRuns` is **all-or-nothing**. For `€2 500\n7` it tokenises
maximally to `2 500\n7`, finds the fused reading (25007) harmless, then splits on
*every* whitespace run into `2`, `500`, `7` — and the grouped reading `2 500`
= 2500 is never considered. The protected amount sits in a whitespace-grouped
*subsequence*, which the current logic can only see if it is the whole token.

This is threat-model vector (b) — a human pasting a price, then a digit landing
nearby. It is not the accepted doubled-space limit.

## 1 — Fix the segmentation (blocking)

Replace the all-or-nothing fallback with segmentation that considers valid
whitespace-grouped **subsequences** before treating a later whitespace run as a
gap. Every reading a human would see must be checked, not just the two extremes.

Constraints that must survive: splitting stays whitespace-only and never splits
on `.` or `,`, so every r1 S1 control keeps its current verdict; a genuinely
fused protected amount is still reported **once** (`€1 560` must not become two
findings); and the `€70\n120` / `€2500\n7` masking cases that r5 fixed must stay
fixed.

## 2 — Fix the corpus, which is the real defect (blocking)

The corpus passed while four shapes regressed. It covers punctuation-grouped-
plus-gap and bare-integer-plus-gap, but **not their composition** — it is
self-consistent, not complete. Enumerating chosen examples is what let this
through, and it is the third time a hand-picked list has missed a composition.

**Generate the differential instead of listing it.** Cross the protected
spellings (each amount × each grouping style × each separator in the `\s` family
and NBSP/narrow/thin) with each adjacent-context shape (nothing following, a
digit after one space, a digit after a newline, a second amount following, a
currency marker before vs after). Assert each generated case against its
expected verdict.

Then **run the generated corpus against `ca8e024`'s scanner as well as your own**
and state every difference in both directions. That comparison — not a
hand-written list — is the artifact that proves no coverage was lost. If the
generated set is large, that is fine; it is a pure string function.

## 3 — S1: leading zeroes from scientific shifting (should-fix)

`canonicalAmounts` claims to return every value a token can denote, but `€0.25e4`
(= 2500) shifts to `02500` and fails to match, as does `€0.1e4` (= 1000). Not a
regression from `ca8e024`, and no shortest-form minifier emits it, but it
contradicts the function's stated contract. Either normalise leading zeroes, or
narrow the contract in the comment and pin the limitation explicitly in the
corpus. Do not leave the contract claiming something it does not do.
