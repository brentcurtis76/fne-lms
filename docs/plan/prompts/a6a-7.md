## Read this first: the scanner is not broken

Sol's round-5 review found **no functional defect in the guard**. It confirms
HEAD catches every separator, its independent span audit found zero attribution
losses across all 928 cases, and the production scan is clean. The PM
additionally derived the ECMAScript whitespace set from the engine — 25 code
points — and confirmed **HEAD misses none of them**.

What is wrong is the **evidence**, in two ways that would let a future
regression through. That is the whole scope of this round. Do not redesign the
scanner.

## 1 — Derive the separator set; do not enumerate it (blocking)

`price-leak-corpus.mjs` lists 18 of the 25 whitespace code points, omitting
U+2001, U+2002 and U+2004–U+2008. The PM's independent generator listed 21,
omitting four. **Hand-enumeration of this dimension has now been wrong three
times, in three different ways, by three different authors.** Adding the seven
missing characters is not the fix — it repeats the method that keeps failing.

Derive the set at test time:

```js
const WHITESPACE = [];
for (let c = 0; c <= 0xffff; c++) if (/\s/.test(String.fromCharCode(c))) WHITESPACE.push(c);
```

Then assert the derived set has the size you expect, so a future engine change
is surfaced rather than silently absorbed. Re-run and publish the corrected
differential — Sol computes it as **154** losses at `2158c44` (not 112) and
**231** id changes vs `ca8e024` (not 182), with no new functional loss.

## 2 — Preserve attribution in the oracle (blocking)

`checksFiring()` reduces findings to a **set of check ids**. A case like
`€120 €70` or `€560 560` therefore stays green if the first planted figure stops
firing while the second still produces the same id. **This is exactly the
attribution failure that hid r5's damage** — on `€1 560 7`, r5 fired on the
nested `560` rather than the fee, and every spot-check passed.

Make amount findings expose the canonical amount and the reading's span, and
have the corpus assert **every planted occurrence** rather than a deduplicated
id set. Include same-id multi-amount cases, and marker positions on both sides
and at the window boundaries. Sol verified HEAD is clean here by hand; the point
is that the committed suite must keep verifying it after everyone stops looking.

## 3 — Pin the suppression invariant (should-fix)

The containment argument is sound only because the one nested pair today is
`1560 ⊃ 560`, where the container's window is 120 and the inner's is 12.
Containment alone says nothing about window width. Either assert that invariant
(for every contained protected reading, the container's window is at least as
wide) or evaluate each reading's window before suppressing. Do not leave the
comment claiming a general proof it does not have.

## 4 — Add the real false-positive as a negative control (should-fix)

`lib/services/hour-tracking.ts` puts a cache TTL of `1000` near the FX URL's
`EUR`, and the scanner fires `priced-amount` on it. It does not survive
minification, so the production scan stays clean and nothing is broken today —
but marker distance and association is a dimension the corpus does not vary. Add
that real fragment as a negative control, and tighten association **only** if
you can do so without weakening the commercial-module mutant proof. If
tightening would weaken it, keep the over-firing and pin it as a known limit
with the reason.
