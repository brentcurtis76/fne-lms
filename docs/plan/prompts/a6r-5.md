## B1 — collection cardinalities bypass both layers

The contract walks and mutates **primitive leaves only**; it never changes array shape.
The page publishes several facts derived from `.length`:

```
pages/pasantias.tsx:715   {COHORT_IMMERSION_SCHOOLS.length} escuelas
pages/pasantias.tsx:745   {COHORT_FREE_DAYS.length} días para Barcelona o Europa
pages/pasantias.tsx:946   Los {COHORT_OBJECTIVES.length} objetivos
```

**PM proof:** replacing `COHORT_SCHOOLS.length` with `7` and `COHORT_OBJECTIVES.length`
with `13` passes **21/21**. Sol reproduced the same with `7`, `2`, `3`, `5` and `13`.

These are customer-facing numbers. "7 escuelas" going stale when a school is dropped is
exactly the decay this phase exists to prevent, and it is the one shape the guard was
never built to see.

**Fix:** derive cardinality cases alongside the leaf cases — for every array in
`COHORT_PUBLIC` whose length the page can publish, mutate the *shape* safely (append a
plausible element, or drop one where dropping is safe) and require the **new count** to
appear in the rendered surface. Add a permanent proof that a hardcoded count fails by
name.

Mind the interaction with what r4 built: changing a school array's length also changes
`uniformImmersionDays()` and the immersion/visit split, so a shape mutation must be
attributable — say which assertion distinguishes "the count re-rendered" from "something
else moved".

## B2 — five leaves are declared absent while the page consumes them

`visitSchools[*].tier` sits in `EXPECTED_GAPS` claiming it is inert. **It is not:**
`SchoolDetail` reads `school.tier === 'inmersion'` at `pages/pasantias.tsx:340` to choose
the dark or light card treatment. The declaration reads as inert only because the
mutation appends `zzq`, leaving `visita` and `visitazzq` **on the same side of the
predicate**. Cross the enum boundary and all five report as consumed.

Two things to fix, not one:

1. **Move them to `UNPRINTABLE_LEAVES`** and use a **predicate-crossing** enum mutation,
   so an enum leaf is tested against the boundary the page actually branches on rather
   than against an arbitrary suffix.
2. **The immersion-tier reasons are also wrong.** They state that tier controls the
   immersion figure; `uniformImmersionDays()` (`pages/pasantias.tsx:75`) reads only
   `immersionDays` and never touches tier. Correct the stated reason to what the code
   does.

Add a negative control for hardcoded tier handling — hardcode the dark/light choice and
show it fails.

**This one is partly mine.** r4's prompt named `tier` as a leaf to declare, and my ledger
endorsed the visit-school classification as "right". It wasn't, and a wrong reason
recorded as fact is worse than an acknowledged gap: it tells the next reader the
question is settled. Treat every existing declared reason as unverified and check it
against the code before re-committing it.
