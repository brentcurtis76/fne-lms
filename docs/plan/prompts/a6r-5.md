### B1 — collection cardinalities bypass both layers

The r4 contract walks and mutates **primitive leaves only**; it never changes array
shape. The page publishes several facts derived from `.length`:

```
pages/pasantias.tsx:618   {COHORT_VISIT_DAY_COUNT} días de visitas · {COHORT_SCHOOLS.length} escuelas
pages/pasantias.tsx:715   {COHORT_IMMERSION_SCHOOLS.length} escuelas
pages/pasantias.tsx:745   {COHORT_FREE_DAYS.length} días para Barcelona o Europa
pages/pasantias.tsx:806   Las ${COHORT_SCHOOLS.length} escuelas
pages/pasantias.tsx:946   Los ${COHORT_OBJECTIVES.length} objetivos
```

These are customer-facing numbers. "7 escuelas" going stale when a school is dropped is
exactly the decay this phase exists to prevent, and it is the one shape the guard was
never built to see.

**Fix:** derive cardinality cases alongside the leaf cases — for every array in
`COHORT_PUBLIC` whose length the page can publish, mutate the *shape* safely and require
the **new count** to appear in the rendered surface. A hardcoded count must fail by name,
permanently.

Mind the interaction with what r4 built: changing a school array's length also changes
`uniformImmersionDays()` and the immersion/visit split, so a shape mutation must be
attributable — say which assertion distinguishes "the count re-rendered" from "something
else moved".

*(The uncommitted work implements this via `collectCollections`, a pinned
`EXPECTED_COLLECTION_COUNT = 21`, an `UNCOUNTED_COLLECTIONS` declaration list asserted in
both directions, and a `publishesCount` helper. Judge it; don't assume it.)*
