### 2. `lib/pasantias/leads.ts` — FROZEN, do not edit

Read it; it is short. What you need from it:


## SPECIFICATION — settled by the PM so you do not have to guess

These are decisions, not suggestions. Deviating is allowed but must appear under
DEVIATIONS with a reason.

**GET response shape**

```jsonc
{
  "leads": [ /* rows, newest first by created_at */ ],
  "counts": { "new": 3, "contacted": 1, "converted": 0, "dismissed": 2, "total": 6 }
}
```

**`counts` is computed over ALL leads, never over the filtered set.** Tabs whose counts
collapse the moment a filter is applied are useless, and it is the obvious way to get this
wrong. Test it: request `?status=new` and assert the other counts are still present and
non-zero.

`status` query param: must be one of the four or absent. An unknown value is a 400, not a
silent "all".

`search`: case-insensitive over first name, last name, email and institution. Empty/absent
= no filter.

**PATCH contract**

- `id` required and a uuid-shaped string; unknown id → **404**.
- Body must carry at least one of `status`, `notes` → otherwise **400**.
- `status` present: must be a `LeadStatus` (use `isLeadStatus`), and
  `canTransitionLead(current, next)` must be true. Denied →
  `400 { error: '<es-CL>', allowed: LeadStatus[] }` where `allowed` is derived from
  `LEAD_STATUSES.filter(s => canTransitionLead(current, s))`. **This includes the
  same-status case** — `canTransitionLead(s, s)` is false by design.
- `notes`: trim; empty string → `null`; **cap at 2000 characters**, over-cap → 400 with an
  es-CL message. (The column is unbounded `text`; an admin textarea with no server cap is
  how a table grows a megabyte row.)
- **Write a whitelist of columns — `status` and `notes` and nothing else.** Never spread
  the request body into the update. This is a service-role client; a spread is a
  write-anything primitive.
- Never write `updated_at` (trigger owns it).
- Other methods → `handleMethodNotAllowed(res, ['GET', 'PATCH'])`.

**Page behaviour**

- `getServerSideProps`: no session → redirect `/login`; not `isGlobalAdmin` → redirect
  `/dashboard`. Mirror `pages/admin/tractor-signups.tsx` exactly.
- Rows load client-side from the API (same as tractor-signups) — do not fetch leads in
  `getServerSideProps`.
- The status dropdown for a `converted` lead offers **nothing**; render a disabled control
  or an explicit es-CL "estado final", not an empty select that looks broken.
- CSV filename: `pasantias-leads-<cohort>` is fine. Columns: the visible table columns plus
  message/utm/source/consent version.

**Testing**

Mock `lib/api-auth` at the module boundary exactly as `__tests__/api/pasantias-lead.test.ts`
does — that is the established seam for this table, and there is no lighter one because the
table has no authenticated write path. Read that file's fake-Supabase harness before
writing yours; you can borrow its shape.
