## B1 — BLOCKING: the column names the wrong document

**`brochure_sent_at` is labelled "Ficha enviada". In this project the *ficha* is a different
document, and the difference is the price.**

The evidence, which you should confirm rather than take on faith:

- `pages/pasantias.tsx:709` — the public page's own CTA is **"Descarga la ficha"**, pointing
  at `/api/pasantias/ficha`. That route's header says it is *"Public and price-free by
  construction (D-02)"*. The ficha is the open document a visitor downloads themselves. It
  is never emailed and nothing stamps a column when someone downloads it.
- `brochure_sent_at` is stamped in exactly one place: `pages/api/pasantias/lead.ts` →
  `runAutoReply` → `claimAutoReplyWindow`, guarding `sendLeadAutoReply` in
  `lib/pasantias/emails.ts`. That email's body says **"puedes descargar el programa
  completo"** with a button reading **"Descargar el programa"**, linking `BROCHURE_PATH =
  '/api/pasantias/brochure'` — the document that carries the €2.500 price.

So the admin surface currently tells FNE staff that the free ficha went out when the record
means the priced programme did, and the CSV exports that claim into a spreadsheet. On the one
axis this plan freezes decisions about (D-02, the price boundary), the label states the
opposite of what happened.

**Fix: rename the label to `Programa enviado`** — the email's own vocabulary, so the admin and
the lead are talking about the same object. Three occurrences, all in
`pages/admin/pasantia-leads.tsx`:

- `:168` — the CSV export row key
- `:317` — the table header
- `:453` — `EMPTY_EXPORT_ROW`, the empty-export column template

The row key and the header must stay **byte-identical to each other**:
`ReportExporter.exportToCSV` uses `headers` both as printed header text and as the key path
into each row (`getNestedValue`), so a mismatch silently exports a blank column. The page
already derives `headers` from `Object.keys(exportRows[0] ?? EMPTY_EXPORT_ROW)`, which is why
all three have to move together.

**Nothing else changes. Do not rename the database column, do not touch
`lib/pasantias/emails.ts`, do not touch `pages/api/pasantias/lead.ts`** — both are frozen
A5 files and neither is wrong.

**Test:** add one assertion to `__tests__/components/admin/pasantia-lead-card.test.tsx` (or a
sibling, your call) pinning that the page's export column set and its table headers agree, and
that neither says "Ficha". A source-level assertion is fine and is the idiom this repo uses.

## S1 — authorized in this round: both layouts mount, so the card renders twice

`pages/admin/pasantia-leads.tsx` renders the desktop table inside
`<div className="hidden overflow-x-auto … md:block">` (~:304) and the mobile list inside
`<div className="space-y-3 md:hidden">` (~:389). **Tailwind hides one with CSS; it does not
unmount it.** Both are in the DOM at every viewport, so an expanded lead mounts
`<PasantiaLeadCard>` twice and the document ends up with two elements carrying
`id="lead-status-<leadId>"`, two carrying `id="lead-notes-<leadId>"`, and two of every
`data-testid` the card emits.

Two consequences, and the first is the one that matters:

1. **`htmlFor` binds to the first matching id in document order — the hidden desktop control.**
   On a phone, tapping the visible "Cambiar estado" or "Notas internas" label focuses a
   `display:none` element, i.e. nothing. `CLAUDE.md` names low-end hardware and small screens
   as a hard requirement, so this is the device class the project explicitly cares about.
2. Duplicate `data-testid`s make any future Playwright selector strict-mode-ambiguous. The r1
   e2e dodges this today only because it asserts on institution text with `.first()`.

**Fix it however you judge best; two obvious shapes:**
- render the expanded card **once**, outside both layout containers (simplest, and it makes
  the duplication structurally impossible), or
- give the card a `domPrefix`/`instanceId` prop so the two mounts generate distinct `id`s and
  `data-testid`s.

Prefer the first unless the layout fights you. Say which you chose and why.

**Test:** render the page-level list (or the card twice, matching whatever shape you ship) and
assert there is exactly **one** element for each of the card's `id`s and `data-testid`s when a
lead is expanded.
