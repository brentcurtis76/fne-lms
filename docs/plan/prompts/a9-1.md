### The public lead endpoint — `pages/api/pasantias/lead.ts` (421 lines)

`POST /api/pasantias/lead`. Read these facts carefully; two of them decide what your spec may
assert.

- **The response is deliberately uniform.** Both the new-lead path (line 416) and the
  already-known-address path (line 300) return `200 {"success": true}`. It reveals nothing about
  whether a row was created or what state it is in. This is why the plan's evidence fix
  (**R2-S-01**) requires persistence to be asserted **through the admin API as the admin
  fixture**, and explicitly **not** through the public response.
- **Uniqueness is on `(email_normalized, cohort)`.** A second submission of the same address for
  the same cohort **updates** the existing row rather than inserting (lines 373–395), and may
  re-open a `dismissed` lead to `new` because `dismissed → new` is a legal D-03 edge. **Therefore
  your spec must mint a fresh unique address per test run** — otherwise the second run takes the
  update path and asserts something different from the first.
- **`brochure_sent_at` is not "the brochure was sent". It is the auto-reply's atomic claim
  stamp.** `runAutoReply` (lines 234–281) resolves the brochure URL, atomically claims the 24h
  window by stamping `brochure_sent_at = now` (`claimAutoReplyWindow`, lines 176–210), sends, and
  then — if the send failed in a way that proves nothing left the process — **releases the claim
  by restoring the previous value** (lines 271–275).
- **In CI there is no `RESEND_API_KEY`** (confirmed: the string does not appear anywhere in
  `.github/workflows/ci.yml`). So the CI path is exactly:
  `sendLeadAutoReply` → `{sent:false, failure:'not_configured'}` (`lib/pasantias/emails.ts:266–270`)
  → `canReleaseAutoReplyClaim` returns **true** (`emails.ts:67–69`: `!sent && failure !== 'unknown'`)
  → the claim is released → **`brochure_sent_at` ends up `null`.**
  **Assert `brochure_sent_at === null`, and assert it as the release contract working**, not as
  an absence you shrugged at. `emails.ts:60–62` states the intent in so many words: a missing key
  must not silently mark a lead as "brochure sent" for a day when nobody was ever mailed. That
  sentence has never been executed end-to-end. Your spec is what executes it.
- `consent_notice_version` is stamped **server-side** from `PRIVACY_NOTICE_VERSION`
  (`lead.ts:23` imports it from `lib/legal/privacy-notice`; written at `lead.ts:80`). Assert
  against the **imported constant**, never a copied literal.
- `buildBrochureUrl()` → `buildAbsoluteUrl('/api/pasantias/brochure')` (`emails.ts:29`, `111–113`).
  It needs `NEXT_PUBLIC_BASE_URL`, which CI sets to `http://localhost:3000`, so it will not throw.
