# CODEX REVIEW — A4 final (two rounds)

VERDICT: FAIL

The round-r2 production-only cache gate is correct and closes the
cross-environment poisoning finding raised after r1. Cache hits, RFC 5987
headers, generate-and-serve degradation, the commercial-import boundary, and
the request-independent CTA origin also satisfy the inlined A4 criteria at PR
head `c2ecb21`. One D-05 durability defect remains: a generated write can
overwrite the owner's manual override even though an ordinary successful cache
hit is served verbatim.

BLOCKING:

- [B1] Generated cache fills are destructive and can overwrite the D-05 manual
  override — `lib/pasantias/pdf/serve.ts:100-126`,
  `lib/propuestas/storage.ts:28-34` — every `downloadFile` error is treated as a
  miss, after which production calls the shared `uploadFile`; that helper uses
  `upsert: true`. Therefore an override that exists throughout a transient read
  failure is replaced by generated bytes if the later upload succeeds. The same
  overwrite occurs if the owner uploads the designed file after a genuine miss
  but before the cold render finishes. The current override test only models a
  successful first read and mocks the destructive storage operation, so it
  cannot detect either ordering. This contradicts D-05's role as a publishing
  mechanism, not merely a cache optimization. Make generated cache fills
  create-only; on an already-exists conflict, preserve the object and preferably
  re-read it for the current response. Keep other upload failures best-effort so
  freshly generated bytes still return 200. Add the transient-read/manual-upload
  race to the route/storage tests.

NOTES ON THE PLAN ITSELF:

- **Normative scope** — I reviewed the inlined criteria in
  `docs/plan/prompts/a4-1.md`, not PLAN's superseded “as v2 A4” shorthand, plus
  the r2 remediation in `docs/plan/prompts/a4-2.md`. Round 1 was reviewed as the
  full serving/header/import-helper implementation; round 2 was reviewed as the
  cache-poisoning remediation. I also checked the last two A4 ledger entries:
  the r2 executor entry and the PM verification at branch head.

- **D-05 ordinary hit behavior is correct but insufficient for [B1]** — both
  routes call `downloadFile` before generation. On a successful hit, the exact
  returned buffer is sent with no generator or upload call. The route comments
  state the manual-override contract clearly, and the parameterized test proves
  the ordinary pre-existing-object case for brochure and ficha. [B1] concerns
  the error/race path after that initial read, where the write is currently an
  upsert.

- **The r2 production-only cache gate passes** — the only A4 generated upload is
  inside `process.env.VERCEL_ENV === 'production'`; `preview`, `development`,
  unset, custom, malformed, and differently cased values all fail closed. Reads
  remain unconditional. Repository inspection found no second Pasantías cache
  writer under `lib`, `pages`, or `scripts`. Vercel documents `VERCEL_ENV` as a
  build-and-runtime system variable whose default-environment values distinguish
  `production`, `preview`, and `development`, so strict equality is the correct
  authority here: https://vercel.com/docs/environment-variables/system-environment-variables.

- **No `NODE_ENV` fallback is the right judgment** — preview and production are
  both production builds, while local `npm start`/build workflows can also carry
  `NODE_ENV=production`. Falling back to it would reopen the exact shared-bucket
  poisoning path r2 exists to close. Off-platform/unset consequently means
  generate-and-serve without writing, which is the safe direction.

- **The CTA origin choice is accepted** — both routes pass zero request object to
  `generateBrochure()` / `generateFicha()`, so neither the request `Host` nor a
  preview deployment hostname can be baked into shared bytes. The generator
  resolves the configured application origin, with the stable Vercel production
  URL as the production fallback. Because only a production runtime may persist
  generated bytes after r2, this configuration-derived, request-independent
  origin is the appropriate interpretation of “pinned”; a hard-coded duplicate
  canonical URL would create a second source of truth.

- **RFC 5987 and headers pass** — `ATTR_CHAR` now matches the §3.2.1 grammar:
  `ALPHA`, `DIGIT`, the punctuation set `! # $ & + - . ^ _ | ~`, and the
  backtick character. It rejects space, `%`, `'`, `*`, separators, controls,
  and non-ASCII input. Encoding is performed per UTF-8
  byte, so `Pasantías` becomes `Pasant%C3%ADas`. Both shipped ASCII constants
  remain valid unescaped `attr-char` values. Both routes emit
  `application/pdf`, the two-form inline `Content-Disposition`,
  `public, max-age=3600`, and the exact buffer length.

- **Generate/degrade behavior passes** — on a production miss each route invokes
  only its own generator and attempts the versioned
  `pasantias/<name>-<VERSION>.pdf` upload. A rejected upload is logged and the
  generated PDF still returns 200. Non-production misses generate and serve with
  no upload. Generator failure returns the es-CL 500 response.

- **C1 and rate limiting pass** — the brochure route is in
  `ALLOWED_COMMERCIAL_IMPORTERS`; the ficha route is expressly absent, and the
  exact importer-set test is green. Both handlers are wrapped in the repository's
  best-effort rate limiter. The post-build leak guard found no commercial data in
  client assets.
