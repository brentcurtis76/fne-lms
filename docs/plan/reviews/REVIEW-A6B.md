## CODEX REVIEW — A6b round 1
VERDICT: FAIL
BLOCKING:
- [B1] Over-limit UTM attribution silently strands an otherwise valid lead — `components/pasantias/LeadForm.tsx:193` — the component copies raw `utm_*` query values into the request body and runs the shared validator before `fetch`; a value longer than `LEAD_FIELD_LIMITS.utm` produces `errors.utmSource`/`utmMedium`/`utmCampaign`, but those fields have no controls or rendered errors and are absent from `FOCUS_ORDER`, so the handler returns with no request, no message, and nowhere to focus. Reproduced against a local production build with a 141-character `utm_source`: zero POSTs, zero visible field errors, no form error, and no focused element after submit. Invisible attribution must not be able to cost the lead: omit/refuse over-limit UTM values before validation/posting (or otherwise make the failure recoverable), and pin the case at RTL and browser level.
SHOULD-FIX:
- [S1] Non-400 responses render an unconstrained server-supplied error string — `components/pasantias/LeadForm.tsx:288` — the current A5 route happens to return generic, PII-free es-CL strings, so this is not a present security or localization failure; however, A6b's contract assigns 429/500/503/network failures to the component's generic es-CL message. Rendering `payload.error` makes that property accidental and lets a future route change expose English or implementation copy. Reserve field payloads for the 400 path and use `GENERIC_ERROR` for every other failure.
NITS:
- None.
NOTES ON THE PLAN ITSELF: D-02's retired-price regex cannot distinguish the frozen message limit `1000` from the former programme amount. `Máximo 1000 caracteres.` is not a price and does not violate D-02's semantic boundary, so its reachable validation state is not a code blocker. The plan/guard should clarify that distinction before asking the form to restore `maxLength`; dropping useful browser-side length enforcement merely to keep an ambiguous digit string out of raw clean-load HTML is the wrong lasting trade. The client import of `validateLeadSubmission` was also audited: it exposes no secret or commercial data, but currently carries about 2.6 KB minified of unrelated signup/RBAC runtime into the page chunk. Given the single-source validation benefit and the still-small `/pasantias` route size (14.4 KB), that bundle cost does not independently warrant rejection; a future extraction of pure normalization/validation into a client-safe leaf would be cleaner.
