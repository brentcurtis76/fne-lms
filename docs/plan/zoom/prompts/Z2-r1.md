## 2. SCOPE — chunk Z2-1: durable managed intent + provision-at-approve enqueue

Server-side only. Six pieces:

**S1. Additive migration** — `supabase/migrations/20260804120000_zoom_managed_intent.sql`:
`ALTER TABLE public.consultor_sessions ADD COLUMN IF NOT EXISTS is_zoom_managed boolean NOT NULL DEFAULT false;`
plus a `COMMENT ON COLUMN` explaining it is durable managed intent per plan §8. Additive
only — no DROP, no TRUNCATE, no destructive ALTER, no RLS change, no new grant.

**S2. Close the eligibility seam** — in `lib/zoom/jobs/meeting-provision.ts`: add
`is_zoom_managed: boolean` to `ProvisionSessionRow`, add the column to the
`readSession` `.select(...)` at `:1266`, add `'is_zoom_managed'` to
`SessionEligibilityCheck`, and add the branch **as the last check** in
`checkSessionEligibility` (`session.is_zoom_managed !== true` ⇒ `'is_zoom_managed'`).
Rewrite the `:451-456` SEAM comment to describe the closed state, not the pending one.
Existing provision tests build session rows without the flag and **will go red** —
update those fixtures; that is expected work, and you must say in the report exactly
which fixtures you touched and why each one is legitimately managed.

**S3. One gate module, no duplicated logic** — new `lib/zoom/provisioning-intent.ts`,
the single source of truth for "does this session get a Zoom meeting, and under what
dedupe key". It must **import and call `checkSessionEligibility`** rather than restate
any of its conditions. Suggested surface (adjust names if the codebase argues
otherwise, but keep the responsibilities):

- `checkProvisionGate(session, env = process.env)` → `null` when the session should be
  provisioned, otherwise a discriminated refusal reason. Check order: master flag →
  `checkSessionEligibility` (which now includes the managed flag) → school allowlist.
- `parseSchoolAllowlist(raw)` → `null` for unset/empty/whitespace-only (= all schools);
  otherwise the set of ids, trimming entries and ignoring blanks. A malformed entry
  must not silently widen access to all schools.
- `provisionDedupeKey(sessionId, approvedAt)` →
  `` `meeting_provision:consultor_session:${sessionId}:${approvedAt}` ``.
  **Rationale you must preserve:** a key without `approved_at` is once-ever — a
  dead-lettered job could never be retried by re-approving, because the completed row
  keeps the key forever. Including the approval instant makes a double-click or route
  retry within one approval a `'duplicate'` (correct) while a genuine later
  re-approval mints a fresh job (also correct — the handler is idempotent by
  checkpoint-adopt, so a redundant job is safe).
- `enqueueSessionProvision({ session, approvedAt, queue, env })` → runs the gate, and
  on pass enqueues `{ job_type: 'meeting_provision', payload: { surface_type:
  'consultor_session', surface_id: session.id }, dedupe_key: … }`. Returns the outcome
  including the refusal reason when skipped. **It must never throw** — a queue error is
  caught, logged with the session id and the reason, and swallowed.

**S4. Wire both approve routes.** In `approve.ts`, after the status update commits
(alongside the existing best-effort activity log, same failure semantics), call the
helper with the `approved_at` the route just wrote. In `bulk-approve.ts`, do the same
per updated session after the bulk update. **Approve must never fail because of Zoom
(§8)** — the HTTP response, status code and body are byte-identical whether the enqueue
succeeded, was a duplicate, was gated off, or threw.

**S5. Create-time intent.** In `pages/api/sessions/index.ts` POST: accept
`is_zoom_managed` (boolean) in the body. When true — require `modality` ∈
{`online`,`hibrida`} (else 400, es-CL), force `meeting_provider = 'zoom'`, force
`meeting_link = null`, and **exempt the request from the `:111` meeting_link
requirement**. Persist the flag in `baseSessionData` so every row of a recurrence
series inherits it. When absent/false, every existing behaviour — including the
`:111` 400 — is unchanged.

**S6. The PUT guard.** In `pages/api/sessions/[id]/index.ts`:
- Reject any PUT that sets `meeting_link` to a non-null value when the **stored**
  session has `is_zoom_managed === true` → **409** with an es-CL message along the
  lines of *"Esta sesión usa una reunión Zoom gestionada por la plataforma; el enlace
  no se edita manualmente."* Same rule for an attempt to change `meeting_provider`
  away from `'zoom'` while managed — it is the same invariant wearing a different hat.
- Allow toggling `is_zoom_managed` itself **only** while the stored status is
  `borrador` or `pendiente_aprobacion`, and **only for admins**. Post-approval toggles
  → **409** es-CL (flipping a provisioned session to unmanaged needs the
  `meeting_delete` sync, which is a later chunk and explicitly not yours). Consultants
  attempting the field → **403**, consistent with the existing structural-field rule.
