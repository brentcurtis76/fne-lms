## 3. PM RULINGS — do not choose differently

1. **`effective_minutes` does NOT exist.** §11's `coalesce(effective_minutes/60.0, hours)` is
   the Z7 end state and that column is Z7's additive migration. The helper reads `hours`
   today behind a **named SEAM comment** describing exactly what Z7 changes — the device
   `meeting-provision.ts` used for `is_zoom_managed`, which Z2-1 then closed cleanly.
   **Do not add the column. Do not add a migration.**

2. **Ledger status carries meaning that `hours` does not — and this is the trap.**
   PM-verified: `executeCancellation` (`hour-tracking.ts:470-481`) updates **only `status`**,
   `cancellation_clause`, `cancellation_reason`, `admin_override*`, `updated_*`. **It never
   changes `hours`.** So a `devuelta` row still holds the full originally-reserved amount even
   though those hours were returned to the school. Therefore:
   - **Per-session display** (the school drill-down): use the row's `hours` verbatim. The
     status is already rendered beside it, so the number keeps its current meaning and the
     change is behaviour-preserving for display.
   - **Aggregates** (`analytics.ts`'s `total_hours_actual`): count **`consumida` and
     `penalizada` only.** Exclude `reservada` (reserved, not yet consumed) and **`devuelta`
     (returned — counting it would overstate what the school was charged).** This is also the
     closest honest analogue of what the old field approximated, since
     `actual_duration_minutes` was only ever written at finalize.
   - **Assert all four statuses in both consumers.**

3. **A session with no ledger row falls back to `scheduled_duration_minutes`.** Legacy and
   never-approved sessions have no entry, and a naive retarget would silently drop their
   hours out of a school's report. This fallback is **behaviour-preserving** for those rows —
   `actual_duration_minutes` was only ever a copy of the scheduled value anyway — while being
   corrective for ledgered ones. Document it at the helper and **test it explicitly in both
   consumers**. A report that quietly under-reports is worse than one that errors.

4. **Keep the `total_hours_actual` response key.** `pages/consultor/sessions/reports.tsx:57`
   declares it; renaming breaks that page and this is not a frontend refactor. Change what
   feeds it, not what it is called. **There is no UI label to fix** — PM verified nothing
   renders it (the only KPI card is `total_hours_scheduled` at `:541`). An earlier prompt
   claimed otherwise; that ruling is withdrawn.

5. **`admin_override` rows flow through unchanged** — `hours` is already the adjusted value
   today; Z7 only adds `effective_minutes` beside it.

6. **No migration; proposing one is a stop-and-report.** Z2-3a's migration is still unverified
   against production, and a second unapplied one would compound the failure that broke

7. **Do not fix the two pre-existing defects r11 found** — the `bucketError` `continue` at
