## 1. THE FINDING — the helper contradicts its own contract

`lib/services/billable-hours.ts:73-84`:

```ts
if (!entry) {
  return (scheduledDurationMinutes ?? 0) / 60;      // ← before the mode check
}

if (mode === 'charged_total' && !isChargedStatus(entry.status)) {
  return 0;
}
```

The no-ledger-row branch returns scheduled hours **regardless of mode**. So in
`charged_total` mode — which the module's own doc at `:35-36` defines as *"an aggregate
answering 'what was this school charged'. Only statuses in CHARGED_LEDGER_STATUSES
contribute"* — a session with **no ledger row at all** contributes its full scheduled
duration.

**The incoherence, stated plainly:** the same file at `:45` documents `reservada` as
*"reserved at approval; the session has not happened. NOT charged"* and correctly returns
**0** for it. But a `borrador` session — not even approved — returns its **full scheduled
hours**. The less-committed session counts more. A session that was never approved was
never reserved and was certainly never charged; the billing record has no entry for it,
so the honest aggregate answer is zero.

**Scope of the impact, PM-verified:** `pages/api/sessions/reports/analytics.ts:238-240`
loads sessions filtered only by `is_active`, school, date range and consultant — **there
is no status filter**. So `sessions` includes `borrador` and `pendiente_aprobacion`, and
every one of them now inflates `total_hours_actual`. Previously they contributed 0, because
`actual_duration_minutes` is NULL until finalize. **This is not a legacy-data edge case as
r12's assumption 2 framed it — it is the ordinary state of every unapproved session, and
the KPI is money-adjacent.**

**Whose error:** the PM's ruling 3 said the no-ledger-row fallback applies "in both
consumers", without distinguishing display from aggregate — even though ruling 2 drew
exactly that distinction one paragraph earlier. Rulings 2 and 3 were inconsistent and you
implemented them faithfully.

## 2. THE CORRECTED RULING

**In `charged_total` mode, a session with no ledger row contributes 0.**
**In `per_session_display` mode, it continues to fall back to `scheduledDurationMinutes`.**

Why this is right rather than merely different: the aggregate answers *what does our
billing record say this school was charged*, and an un-ledgered session has no billing
record — including legacy sessions that were delivered but never linked to a contract. They
were not charged through the ledger, so the ledger-derived KPI must not claim they were.
The drill-down is a different question — it renders one row per session and must show
something meaningful for a session that is not ledgered yet — so ruling 3's original intent
stands there, unchanged.

This also makes the module internally consistent: in `charged_total`, **only a ledger row
with a charged status ever contributes**, full stop.
