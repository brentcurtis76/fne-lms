## 1. ITEM 4 — the join route trusts a projection that can be stale

**PM-verified.** `pages/api/meet/session/[id]/join.ts` resolves authorization, then gates on
**two derived sources and never on the source of truth**:

- `session_meetings_public.meeting_status` (`:147-162`) — the **worker-maintained
  projection**, which converges *after* the fact.
- `zoom_internal.zoom_meetings.status` (`:164-182`) — the Zoom-side state machine.

`consultor_sessions.status` and `consultor_sessions.modality` are **never read**.

**The hole.** Cancelling a session updates `consultor_sessions` and *enqueues*
`meeting_delete`; the projection converges later. In that window an **authorized** caller —
a real facilitator or attendee, not an intruder — asks to join a cancelled session and gets
back a **live `join_url`, the passcode, the meeting number and the dial-in set**. The same
is true of a modality flip to `presencial`: the session is no longer an online meeting, and
Z2-3b's own open item already recorded that an edit-request flip leaves the meeting alive.

§15's exit criterion says **"cancel kills join"**. Today cancel kills join *eventually*.

**THE RULING.** Read `consultor_sessions.status` and `modality` and refuse **before any read
of `zoom_meetings`** — credentials must not be fetched, let alone returned, for a session
the source of truth says is over or is no longer online. Order matters and is testable:
the refusal must be reachable with the internal row still fully populated.

**What must not change:**
- **The anonymous and other-school denial semantics are frozen.** Whatever
  `authorizeMeetingJoin` refuses today must be refused identically — same status, same body,
  same non-disclosure. Your new gate runs **after** authorization, exactly where the current
  projection check runs, so it can never turn a 403/404 into a 410 or vice versa.
- The `mode: 'pending'` outcome for a not-yet-provisioned meeting stays a 200 carrying no
  meeting facts.
- The seven documented outcomes in the route header stay accurate — update the header if you
  add an outcome, and say so in the report.

**You choose the closed set** for status and modality, from the existing constants and the
session status enum. **State it explicitly in the report with the reasoning** — this is a
security boundary, not a detail.

## 2. ITEM 9 — the SSR page enforces neither the join policy nor the kill switch

**PM-verified.** `pages/meet/session/[id].tsx:128-158` calls `resolveMeetSessionAccess`,
which yields `unauthenticated` → login redirect, `not-found` → `notFound`, otherwise props.
It **never calls `authorizeMeetingJoin`** and **never checks the feature flag**.

So the platform has **two different authorization helpers for the same surface**:
`resolveMeetSessionAccess` for the page, `authorizeMeetingJoin` for the API. That is exactly
the drift this workstream keeps eliminating — the rule that produced
`lib/utils/session-scope.ts`, `lib/services/billable-hours.ts` and
`lib/services/session-lifecycle-notifications.ts`.

**THE RULING.** The SSR page enforces the **same** policy the API does, and the §14 kill
switch, per PLAN §§5 and 14. **One implementation** — either the page calls
`authorizeMeetingJoin`, or `resolveMeetSessionAccess` delegates to it. You pick; **prove
there is exactly one policy implementation** with a grep in the report.

**Three behaviours that must survive, and they are the reason this is delicate:**
1. **The login redirect**, carrying `next=` so the join link still works after logging in
   (`:141-152`). An unauthenticated visitor must still be redirected, not 404'd.
2. **No existence oracle.** A logged-in user who is not entitled to this session must get
   the **same** response as one asking for a session that does not exist. Today that is
   `notFound`. Do not introduce a distinguishable "forbidden" page, and do not leak
   existence through timing-free differences like a different redirect or status.
3. **The kill switch.** With `FeatureFlags.ZOOM_MEETINGS` off, the API answers 503
   (`FEATURE_DISABLED_MESSAGE`). Decide what the page does and **state why**; whatever you
   choose must not become an existence oracle either.
