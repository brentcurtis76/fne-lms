## 2. SCOPE — chunk Z2-2a: the authorized join opening (server only)

Plan §5: *"everything Zoom-credential-shaped lives server-side… Exactly one narrow
per-request opening: the authorized join payload from `POST /api/meet/{surface}/{id}/join`."*

**S1 — `lib/utils/meeting-join-policy.ts`, exporting `authorizeMeetingJoin()`.** The
single source of truth for join authorization, per §5's matrix. Consultor sessions only.
It must be pure-ish and unit-testable the way `session-meet-access.ts` is: take the
service client, the session id and the user id; return a discriminated result. The §5
matrix, verbatim and normative:

| Persona | Result |
|---|---|
| Admin | authorized, host-capable |
| Assigned facilitator (row in `session_facilitators`) | authorized, host |
| Expected attendee (`session_attendees` with `expected = true`) | authorized, participant |
| Active GC member NOT in attendees | **403** es-CL: *"No estás en la lista de asistentes de esta sesión…"* — remedy is that a facilitator adds them |
| Same-school non-facilitator consultor | **403** — *el asesor nunca lee contenido crudo de sesiones ajenas* |
| Other-school user | **404**, byte-identical to a nonexistent UUID |
| Anonymous | **401** |

**S2 — `POST /api/meet/session/[id]/join`.** Uses `authorizeMeetingJoin`. Decision order
matters and is itself an acceptance criterion — **authorization is fully resolved before
anything about the meeting's state is revealed**, or the endpoint becomes an existence
oracle for meetings:

1. Not `POST` → 405 (match `handleMethodNotAllowed` usage in the repo).
2. No session → **401**.
3. `FEATURE_ZOOM_MEETINGS` not `'true'` → **503** es-CL: *"Las videollamadas están
   temporalmente deshabilitadas"* (§14). Place it here — before any lookup — so the kill
   switch reveals nothing either.
4. `authorizeMeetingJoin` → 404 / 403 per the matrix above.
5. Only now read the meeting. Projection `meeting_status` is `'cancelled'` or `'ended'`
   → **410** es-CL, for **every** persona including admin (§5).
6. No `zoom_meetings` row yet, or its `status` is not one a participant can join →
   **200 with `{ mode: 'pending' }`** (PM ruling, §3 below).
7. Otherwise → **200** with the link-mode payload.

**The link-mode payload**, and nothing more: `{ mode: 'link', join_url, role }` where
`role` is `'host'` for admin/facilitator and `'participant'` otherwise. `join_url` comes
from `zoom_internal.zoom_meetings` through the service client. **`FEATURE_ZOOM_EMBED` is
not read in this chunk** — embed mode is Z3; link mode is the Z2 default (§15).

## 3. PM RULINGS — do not choose differently

1. **"Not provisioned yet" is `200 { mode: 'pending' }`, not an error.** §8 says the UI
   shows *"Enlace en preparación"* until the projection row lands. The endpoint's job is
   "tell me how to join"; "not yet" is a legitimate answer in the same `mode` vocabulary
   §5 already uses (`mode:'link'` vs `mode:'embedded'`). A 4xx would make the normal
   seconds-long window after approval look like a failure.
2. **No ZAK, no SDK signature, no `role:1` issuance in this chunk.** §9's ZAK rules and
   §5's SDK JWT are the embed path (Z3). `role` here is descriptive metadata for the UI,
   not a credential. If you find yourself importing `lib/zoom/signer.ts`, stop.
3. **`authorizeMeetingJoin` must NOT be built by wrapping `canViewSession`.** They answer
   different questions and §5 is explicit that an active GC member who can view gets
   **403** on join. Reuse the role/facilitator lookups if that is natural, but the
   decision is its own.
4. **404 vs 403 must be byte-identical to the existing denial vocabulary.** Reuse
   `lib/utils/session-denials.ts` (`sendSessionNotFound`) — Z1c's whole point was that a
   denied session returns `404 'Sesión no encontrada'`, and a new endpoint that invents
   its own 404 body reopens the oracle from the other side.
5. **Do not modify `resolveMeetSessionAccess`, `pages/meet/session/[id].tsx`, or
   `tests/e2e/zoom-join-authz.spec.ts`.** The page and its e2e matrix are Z2-2b's, and
   changing the interstitial's semantics underneath a blocking CI spec in a chunk that
   ships no UI is how a green gate stops meaning anything.
