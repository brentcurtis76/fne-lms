## PM RULINGS — decided. Implement them; do not re-litigate.

**① The client still NEVER reads the embed feature flag.** `mode` in the response is the only
signal. `[C11]` in `__tests__/components/sessions/JoinMeetingButton.sdk.test.tsx` enforces this
mechanically by reading the component sources off disk — **extend that guard to any new client
module you add**, do not work around it.

**② `supportsComponentView()` must exclude Firefox — the PM ruled against r3's reading.**

r3 left desktop Firefox on Component View. `PLAN.md` **line 403** (a line, not a section —
the plan has no §403) reads:

> Component View desktop-only (mobile = Client View; **Firefox/Android unsupported**)

r3 read the second clause as modifying Client View. **That makes the parenthetical contradict
itself**: Android *is* mobile, so "on mobile use Client View" followed by "Client View does
not support Android" would leave Android with no path at all. The coherent reading is that
both clauses describe **Component View** — desktop-only, use Client View on mobile, and
unsupported on Firefox and Android.

Today a desktop Firefox user downloads the **3.7 MB** bundle, fails, and only then falls back.
`CLAUDE.md` requires this to work on "older school hardware (low-end browsers, small
screens)" — a wasted 3.7 MB on a slow school link is exactly the cost this phase exists to
avoid.

**This ruling is the PM reading a compressed doc-verification note, not a fresh check against
Zoom's live support matrix.** If you can confirm or contradict it cheaply against Zoom's
current documentation, do — **a contradiction is a FINDING worth reporting, not a reason to
quietly keep r3's branch.**

**③ After a blocked popup, the retry control must re-run the FALLBACK, not the embed.** r3's
message says *"Presiona «Unirse a la reunión» otra vez para abrirla"*, but that control
restarts the SDK flow, so the user pays another failed embed attempt first. It works, but it
is the wrong thing to do twice.

**④ Client View is the mobile path, and it is a DIFFERENT SDK surface.** Component View
(`ZoomMtgEmbedded`, renders into your element) and Client View (`ZoomMtg`, takes over the
page) are different globals, different bundles and different init/join calls. Do not try to
make one module serve both by branching deep inside it — the loader and the join call differ
from the first line. `pages/meet/diag.tsx:43-146` remains the reference for the *pattern*
(externalised React, sequential vendor loading), not for Client View's specific API.

**⑤ `pages/meet/diag.tsx` and `pages/api/meet/diag-signature.ts` stay untouched.** The field
