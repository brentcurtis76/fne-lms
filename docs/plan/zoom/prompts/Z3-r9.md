## WHAT THIS ROUND IS

Z3 now ships **Component View on desktop only**. Client View moves to a new phase **Z3b**,
sequenced behind a Client-View-specific field protocol that does not exist yet. Everything
already built stays; **nothing is deleted.**

Four items, and the second is the one that matters.

### 1. Sol M4 — the request-path ZAK call has no bounded failure path

`pages/api/meet/session/[id]/join.ts:478` awaits `getUserZak()` inside an HTTP request. The
transport has **no `AbortSignal` and no deadline** — verified: `grep -cE "AbortSignal|AbortController|signal:"`
over `lib/zoom/client.ts` and `lib/zoom/api.ts` returns **0 and 0** — and it inherits the
worker-oriented retry policy (3 attempts, up to two 60 s `Retry-After` waits), plus unbounded
transport and token-provider waits.

A call that never settles means the route **never reaches its link response**, and the hosting
platform's timeout produces an error — contradicting the route's own header at `:78`, which
promises every SDK failure degrades to link mode.

**Required:** a **total request-scoped budget** with an `AbortSignal` propagated to the actual
fetch and token work. Do **not** let background-worker retry waits consume a request lifetime.
**Budget exhaustion returns the existing 200 link-mode payload and writes NO issuance audit
row** — a credential that never arrived was never issued. Test a never-settling transport and
repeated `429`/`Retry-After`.

### 2. Structural unreachability — the DoD clause that lets Sol M3 defer

**Read this twice. If it is not fully satisfied, M3 has not moved and the split does not hold.**

`PLAN.md` §15's Z3 row now requires: **on every non-Component path, link mode is requested
BEFORE any Client View bundle, iframe, SDK/media worker or Client View join is started**; and
a host on that path **mints no ZAK and writes no `zoom_zak_issuances` row** for a credential
that will be discarded.

**The reviewer's Note 1, which the PM verified and which is the trap here:** the three obvious
populations — mobile, tablet, Firefox — are **minimum coverage, not the definition.**
`selectEmbedView()` is `component → client → none` (`lib/meet/embed-capabilities.ts:109`), and
`supportsComponentView()` **rejects viewports under 768 px** (`:58`). **So a narrow DESKTOP
window also selects Client View** — a split-screen user, a low-resolution school monitor, a
restored-down browser. Three isolated UA tests would miss it.

**Required: a truth table over the selector**, covering every branch that can yield a
non-`component` outcome, each asserting that the join request goes out in link mode and that
**no Client View loader, iframe, bundle or SDK call is reached.** Assert the loaders were **not
called**, not merely that nothing rendered.

**How you achieve it is yours to choose** — the natural shape is that the client asks for link
mode when it knows Component View is unavailable, so the server never mints an SDK payload it
cannot use. **Keep PM ruling ① from r3: the client still never reads the embed flag.** If your
approach requires the server to know the view, that is a wire-contract change and you must say
so explicitly rather than slipping it in.

**Do not delete the Client View code.** It is Z3b's starting point. Make it unreachable, keep
it compiling, keep its tests green.
