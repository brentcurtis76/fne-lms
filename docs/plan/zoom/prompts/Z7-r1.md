## 3. Scope — chunk Z7-1 only

**One architectural concern: the attendance data plane and the actual-elapsed instants.** No
ingestion logic, no UI, no override machinery — those are Z7-2 … Z7-5.

**(a) Migration — `public.zoom_attendance`** per §6/§7. One row per person per interval:

- `id uuid PK`, `surface_type text NOT NULL CHECK (surface_type IN ('consultor_session','community_meeting'))`,
  `surface_id uuid NOT NULL`, **`school_id integer NOT NULL REFERENCES public.schools(id)`** (the
  §6 invariant — every public row is school-scoped), `zoom_meeting_uuid text NOT NULL` (the
  occurrence key, not the meeting number).
- Identity: `user_id uuid NULL REFERENCES public.profiles(id)`, `customer_key text NULL`,
  `display_name text NULL`, `transient_email text NULL`, and
  `matched_by text NOT NULL CHECK (matched_by IN ('customer_key','email','name','unmatched'))`.
- Interval: `joined_at timestamptz NOT NULL`, `left_at timestamptz NULL`.
- Provenance: `source text NOT NULL CHECK (source IN ('webhook','report'))` — Z7-3 needs this,
  because §11 makes the reconcile report **authoritative over webhooks** rather than additive.
- `created_at`, `updated_at`. Indexes on `(surface_type, surface_id)` and `(zoom_meeting_uuid)`.
- **RLS enabled. SELECT policies only — no INSERT/UPDATE/DELETE policy for any role.** Per §7:
  admin all rows; the facilitator of that surface; a consultor **only where they are the
  facilitator**. Nobody else, including GC members and every ED/LG/SR/CM/EL role. Follow `010`'s
  predicate patterns (admin via `user_roles`, facilitator via `session_facilitators`).

**(b) Migration — the C6 amendment.** Additive nullable `actual_started_at timestamptz` and
`actual_ended_at timestamptz` on `zoom_internal.zoom_meetings`. Column comments must say what they
are and that provisioning never writes them.

**(c) Lifecycle writes the instants.** Extend the existing guarded transition in
`lib/zoom/webhook-lifecycle.ts` / `lib/zoom/webhook-store.ts` so `meeting.started` records
`actual_started_at` and `meeting.ended` records `actual_ended_at`, read from
`payload.object.start_time` / `end_time`, falling back to `event_ts` (milliseconds) when absent,
and **never** from the header timestamp. **Both writes are `COALESCE(existing, new)` inside the
same guarded UPDATE** — `webhook_sweep` deliberately replays events minutes later and Zoom does
not order deliveries, so a late `started` must not overwrite an instant already recorded. This is
the same reasoning the file already documents for status, and it is why the guard lives in SQL and
not in JS.

**(d) pgTAP.** Append to `supabase/tests/011-zoom-public-rls.sql` in its existing style (raise the
`plan(n)`, synthetic users only, whole file rolls back). Assert: RLS on; the persona SELECT matrix
above including at least one other-school negative and one GC-member negative; **no write policy
exists** (blocked INSERT throws `42501`, blocked UPDATE/DELETE return empty — assert accordingly);
and the two new `zoom_meetings` columns exist, are nullable, and are unreachable by
`anon`/`authenticated` (the §6 lockdown must still hold after your migration).
