## 1. The rule that replaces the fallback ladder

A token may authorise **webhook-time closure** only if all three hold:

1. **Zoom mints it; the client cannot assert it.**
2. **It is unique to one participant-connection by construction** — not merely unique in the
   sample we hold.
3. **It matches exactly one OPEN row in that occurrence.** Zero or >1 ⇒ close nothing.

| Token | Ruling |
|---|---|
| `participant_uuid` | **authorises closure**, subject to rule 3 |
| `customer_key` | **reconciliation only** — we mint it and hand it to the browser, so it is a claim, not an identity (rule 1). Z0B §6.2's byte-identical result measured the *report* round trip, not webhook pairing |
| `email` | reconciliation only — `""` for every signed-out guest (§6.2) |
| `display_name` | reconciliation only — this is the H1/H2 defect |

**Unproven `participant_uuid` stability is no longer a blocker and you must not try to prove
it.** Under rule 3 an unstable token matches nothing, the interval stays open, and Z7-3 closes
it: instability degrades to no-closure, which is safe. Closing the *wrong person's* interval
would need a UUID collision inside one occurrence.

4. **No retroactive pairing, ever.** A leave observation is never re-applied to a join that
   arrives afterwards.
