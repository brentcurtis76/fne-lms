## Scrutinize hardest
1. **Active bell gear placement and closing.** The gear closes the panel on every click, including Ctrl/Cmd-click (the new tab still opens; the original page stays). The dropdown is `fixed` inside the transformed sidebar, so on a 390 px phone the panel is clipped at the sidebar's bottom edge (pre-existing); the gear sits in the header and is asserted in viewport.
2. **Cold loads of `/notifications` and `/profile` bounce to `/dashboard`** (no `initialSession`; `useSession()` starts null and the page pushes `/login`). Pre-existing (N21-A3, routed to the navigation backlog). The e2e reaches both in-app.
3. **Middleware addition** — the anonymous pass-through for `/configuracion` is deliberate (matches the other non-legacy prefixes; SSR redirects with `next`). Check that nothing now requires a role there.
4. **E-mail footer placement** — the link lives inside the closing `<p>` so the shared-shell test in `__tests__/lib/email/invitations.test.ts` (not in the allowlist) still compares identical fallback markup. The legacy template keeps `NEXT_PUBLIC_APP_URL` (as its sibling links do) rather than `getAppBaseUrl()`, so it adds no new production throw.
5. **Test seams** — the unit suite drives the real components/pages with a mocked Supabase client and a real Next `RouterContext`; the Sidebar caller is checked by source (rendering the 1500-line Sidebar would need most of the app mocked), the real Sidebar path is covered by the browser journeys.
