## Reviewer hotspots — round 5 (my own judgment calls — descending importance)

1. **`FOR SHARE` vs a stronger lock.** `FOR SHARE` on the template row blocks every `UPDATE` (archive, restore, publish flip) but not a snapshot `INSERT` (its FK check takes `KEY SHARE`, compatible). I chose it over `FOR NO KEY UPDATE` so concurrent attaches for different courses under the same template do not serialise on the template row. The trade is documented: the current-snapshot check is not lock-protected (§ above). If Codex considers the residual (instance on the previous snapshot) an access decision, the enforceable fix is to make `publishTemplate` lock / update the template row **before** inserting the snapshot; I did not change the publish path.
2. **Step 2e is procedural, not cascaded.** Archiving a template does not archive its live instances in the same transaction; the invariant enforced is "no live instance can be created under a template whose archive already committed", and 2e (run from a post-archive Step 1c listing) archives the ones that existed before. A cascade trigger on `is_archived` would be a product change (it would archive in-progress instances with responses) and is not in scope; it is listed under open decisions.
3. **The 2e refusal path in [2e-r5a].** Codex's step 6 (2e for I4 succeeding while the attach waited) is only reachable if the archive committed first, which the lock now prevents; the proof therefore shows 2e **refusing** at that point. The operator's aborted transaction is what releases the boundary in that scenario; in production the operator would `ROLLBACK`, re-run Step 1c after the archive and run 2e from it.
4. **ULP tolerance = 8.** The measured worst case is 2 ULP over a broad sweep; 8 gives a 4× margin. The tolerance still scales with the magnitude of the number (it is the double's last place), so at 1e9 it is ~1e-6 — that is the precision of the representation itself, and no configured step can be finer than it. The min < max comparison is exact by design (a 1-ULP range is a range).
5. **Records only, no code, in the third commit.** The commits are ordered implementation → tests → records as required.

## Reviewer hotspots — earlier rounds (retained)

1. **`save_transversal_context` locks every course row of the school `FOR UPDATE`**, not only the ones to be removed. It is what closes the check-then-delete race (KEY SHARE conflict), at the cost of briefly blocking any concurrent assignment/instance INSERT on surviving courses of that school. 2. **The consultor deny is temporary and total** (GET included). 3. **`courses_per_level` normalisation** — unchanged from PR 2 (only submitted levels are kept), now enforced in SQL too. Deselecting a level makes its courses removal candidates, which the dependency block will refuse if any history exists.
4. **Snapshot content parity is proven against the service in a fake client**, and the loopback proof verifies it against real PostgREST; a hosted PostgREST that serialises numerics differently would be caught by the numeric-string coercion (against the expected payload only) — a string in a place the expectation has a number is coerced, nothing else is.

That is intended (drift is a stop, never a bypass), but the first staging run may need a reviewed regeneration from the staging catalog — which is itself a decision, not something the tooling does.
